卡券实例处理及角色权限 · 需求说明 V1.4

需求ID：DFN-REQ-20260916-002；优先级：P0（紧急）；对应功能清单序号9、10。日期：2026-09-22。

1. 目标与范围

在现有作废页合并解冻功能，页面改名“卡券实例处理”，沿用原入口与地址，不另增页面。通过卡券模板ID＋核销码确认唯一实例，并校验手机号/VIN。未使用、已冻结、已过期可作废；已冻结卡券还可解冻，有效期内恢复未使用，超期恢复已过期。角色授权及后台重验以本地模拟表达，不执行真实卡券处理、授权或发布。

对象是单个卡券实例。同模板下其他实例、模板本身不随本动作改变。相关DFN-REQ-20260824-001模板禁用为另一需求，不以模板禁用替代本需求，不扩展批量作废、退款、补发或撤销能力。

2. 来源与证据等级

依据用户确认的单实例定位、冻结和过期可作废、操作记录独立弹窗及操作人、同页解冻与作废规则。解冻按原有效期恢复状态，不新增已失效枚举。其余接口、权限粒度、审计和联动仍待确认；页面均为虚构数据评审。

4. 页面与字段

操作页输入：手机号、VIN码、卡券模板ID、核销码。模板ID与核销码必填来自S01；手机号与VIN填写关系见Q01。原型演示暂采用“至少填一项，同时填写须均匹配”，非正式口径。手机号按11位数字、VIN按17位无I/O/Q的英文数字演示；真实支持范围和格式待确认。模板/核销码仅做非空与虚构数据精确匹配，不捏造正式编码格式。

用户已确认：系统没有卡券实例ID业务参数，通过“卡券模板ID＋核销码”确认一个实例。手机号/VIN继续作为现有校验条件，其填写关系仍见Q01。点击“校验并定位”前无目标实例；结果和确认弹窗优先展示模板ID与核销码，再展示卡券名称、手机号、VIN及状态。操作记录使用模板ID与核销码，不再展示或要求实例ID。模板ID＋核销码匹配结果仅一条且手机号/VIN校验通过，再按状态和所选动作授权显示按钮；结果未唯一不允许人工任选。输入任一条件变化、切换身份均使旧定位失效。

用户已确认已冻结、已过期也可以作废（S08）。当前原型可作废状态为未使用、已冻结、已过期；已核销等未确认状态保留原状态，已作废不重复执行。定位后状态或版本变化时仍须重新校验，重新定位到已冻结/已过期实例后可继续作废。

冻结卡券同页增加“解冻此实例”，与“作废此实例”并列。解冻确认展示目标信息、有效期及预计恢复状态；超期明确提示解冻后仍不可使用。提交时重新按有效期判断恢复状态，不延长或重置有效期。缺失或倒置有效期、尚未到有效期开始时不解冻，边界策略见Q11。示例有效期由加载时间生成，包含有效期内冻结与已超期冻结两种样例。

确认弹窗属于设计建议：再次展示目标摘要、可选操作原因，取消保留原状态；原因不设必填，不设审批。提交期间阻止重复触发；提交再次核对组合、实例状态和权限。

操作记录按用户确认S09移至独立弹窗，页面标题右侧提供“操作记录”入口，有记录时显示数量。弹窗每次打开读取本次会话最新记录，展示操作时间、操作人、示例角色、操作类型、卡券模板ID、核销码、脱敏手机号/VIN、结果与操作原因，共10列；无记录展示空状态。支持关闭按钮、右上角关闭与Esc，关闭不清空记录、不改变查询条件或定位结果。操作人单独展示当前登录用户名称，模拟提交时记录操作人和角色快照，之后切换角色不改写已有记录；当前Mock账号为“演示用户”。记录仍限本次会话，刷新或重置演示后清空；多条记录在弹窗内滚动。

角色页暂称“角色管理”，提供角色列表、独立查看态、独立配置态。角色名称、编码、状态、功能树是评审结构，不声称已与现有SIT字段逐项一致，也不替代现有角色页全量字段；正式增量必须保留现有字段和原权限树。本轮在示例树中保留“卡券实例作废”并增加“卡券实例解冻”两个动作叶子；任一授权允许进入统一页面，每个按钮及提交按对应授权检查。这是原型表达，正式页面/查询/动作权限粒度仍待Q06；不模拟其他历史权限。示例运营角色与普通角色均为虚构，不作为具体授权名单；权限配置演示只由示例权限管理员进入。

6. 后台职责与系统边界

正式后台必须在查询及提交分别检查账号、角色功能权限与允许的数据范围；前端隐藏按钮不能替代鉴权。提交应按卡券模板ID＋核销码重新定位目标，并核对手机号/VIN及最新状态；解冻须使用正式有效期和后台当前时间判断恢复结果，不引入卡券实例ID参数。正式字段映射、枚举、接口地址、协议及错误码未取得，示例字段不构成接口合同。

本需求下游同步范围、状态生效点、顺序及失败补偿均待确认。待评估用户卡包、下单/锁券、核销、结算、补贴、库存和车联网副本；不能由本原型成功推断已同步。如后续涉及车联网，沿用已确认“卡券中心→新商城透传→车联网”的系统边界，不画直连。本次流程只到卡券中心单实例处理结果，下游以待确认旁注表示。
